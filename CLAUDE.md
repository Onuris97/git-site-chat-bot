# GRACE Rules

## Перед любым изменением
1. `cat docs/Architecture.xml` — граф модулей (КОМПАКТНЫЙ, читай ВСЕГДА)
2. `cat docs/Contracts.xml` — индекс контрактов (КОМПАКТНЫЙ, читай ВСЕГДА)
3. Найди нужную подсистему → `cat docs/contracts/contracts-<подсистема>.xml` (только нужный)
4. `grep -rn "GRACE:MODULE_START" src/` — навигация по коду

## Навигация по GRACE-документации

Документация разбита на части. НЕ читай всё — читай только нужное:

1. `docs/Architecture.xml` — КОМПАКТНЫЙ граф верхнего уровня (читай ВСЕГДА)
2. `docs/Contracts.xml` — ИНДЕКС контрактов (читай ВСЕГДА)
3. `docs/architecture/arch-*.xml` — детали архитектуры ПО ПОДСИСТЕМАМ (читай только нужную)
4. `docs/contracts/contracts-*.xml` — детали контрактов ПО ПОДСИСТЕМАМ (читай только нужный)

### Алгоритм для агента:
1. Прочитай docs/Architecture.xml — определи, какая подсистема затронута
2. Прочитай docs/Contracts.xml — найди файл с контрактами этой подсистемы

## Запреты
- НЕ менять контракты без явного запроса
- НЕ удалять GRACE-якоря
- НЕ делать вложенность > 2 уровней

## Правило: Экспорт при межмодульных вызовах (1С)

**Нарушение:** предупреждение "Возможно ошибочный метод: ИмяФункции" в проверке синтаксиса.

При переносе функции из одного модуля в другой:
1. Если функция будет вызываться из других модулей (`МодульX.ИмяФункции(...)`) — добавить `Экспорт`
2. Перед записью любого вызова `МодульX.ИмяФункции(...)` — убедиться что `ИмяФункции` в `МодульX` объявлена с `Экспорт`
3. Приватная функция (без `Экспорт`) доступна ТОЛЬКО внутри своего модуля — вызов из другого модуля невозможен

## Правило: Контекст выполнения общих модулей (1С)

**Нарушение:** вызов функции клиентского модуля из серверного — ошибка компиляции или некорректное поведение в runtime.

Таблица совместимости контекстов:

| Вызывающий модуль        | Может вызывать                                      | НЕ может вызывать               |
|--------------------------|-----------------------------------------------------|---------------------------------|
| Сервер (`Server=true`)   | Server, ClientServer                                | Client, ClientOrdinaryApp       |
| Клиент (`Client*=true`)  | Client, ClientServer, ClientOrdinaryApp             | Server (только через серверный вызов формы) |
| ClientServer             | ClientServer                                        | чистый Server или чистый Client |

**Перед написанием вызова `МодульX.Функция()`:**
1. Открыть `МодульX.xml` и проверить флаги: `Server`, `Client`, `ClientManagedApplication`, `ClientOrdinaryApplication`, `ServerCall`
2. Сравнить с контекстом вызывающего модуля
3. Если контексты несовместимы — вынести вызов в модуль с нужным контекстом или создать КлиентСервер-обёртку

**Типичные ошибки:**
- Серверный модуль вызывает `ЕИС_Клиент.Функция()` → **ЗАПРЕЩЕНО** (клиентский модуль недоступен на сервере)
- Форма вызывает `ГМ_ЕИС.Функция()` где функции нет → добавить делегатор или исправить имя модуля
- `&НаКлиенте` процедура формы вызывает серверную функцию напрямую → только через `&НаСервере`
